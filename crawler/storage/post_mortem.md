# Post-Mortem: チュートリアル自律突破 (2026-03-06)

## KPT 分析

### Keep (継続すべきこと)

- **`roi_to_device()` による ROI 座標補正**: 68 箇所に適用済み。デバイス黒帯オフセットを吸収し、全解像度で安定動作
- **STEP 0 テンプレートマッチング**: `close_x_*.png` による x ボタン先行検出。OCR より高速・高精度
- **Wi-Fi 画像破損リトライ**: `screencap -p` の TCP 損失を 3 回リトライ + ADB 再接続で自動復帰
- **Unity 入力フリーズ自動復帰**: `force-stop` → `am start` で最大 3 回リスタート
- **phash ベースの画面変化検出**: ハミング距離 >= 8 で「大きな変化」、< 8 で「同一画面」を判別
- **強制 OCR トリガー**: 同一画面 5 回超で精査を強制実行し、微細な UI 変化を捕捉
- **二段構え解析 (粗解析 → 精査)**: 低解像度 phash で毎ループ判定、変化時のみフル OCR → トークンコスト大幅削減

### Problem (問題)

| 問題 | 影響 | 発見タイミング |
|------|------|--------------|
| ROI 黒帯オフセット未補正 | ratio-based 座標 18 箇所が最大 49px ズレ → タップ空振り | Phase 中盤 |
| Wi-Fi 画像破損 | `screencap -p` がノイズ画像を返す → 連続 15 回失敗 | Phase 序盤 |
| #0-DIALOG 誤検出 | ホーム画面バナーの金枠を dialog frame と誤認 → 右上設定ボタン誤タップ | Phase 終盤 |
| Canny/輝度 x 検出 false positive | 非ダイアログ画面で x ボタンを誤検出 → 意図しない画面遷移 | Phase 中盤 |
| 公式 SNS リンクタップ | チュートリアル指アイコンが SNS リンクを指していた → ブラウザ起動 | Phase 中盤 |
| ハードコード座標 8 箇所 | `roi_to_device()` 未適用 → デバイス変更時に動作不良の恐れ | Phase 終盤 |

### Try (今後試すべきこと)

- 全タップ座標の `roi_to_device()` 強制適用 (残り 8 箇所 → 本セッションで修正)
- チュートリアル固有分岐の汎用化 (11 ブロック → 3 ハンドラ)
- x テンプレートの複数バリエーション対応 (ゲームごとに x ボタンデザインが異なる)
- `tap_device()` への `_from_roi` デバッグフラグ導入 (未変換座標の検出)

## RCA (根本原因分析)

| 問題 | 根本原因 | 解決策 | 状態 |
|------|---------|--------|------|
| 座標ズレ (ROI) | ゲーム描画領域 != 画面全体。黒帯 L=68 / B=53 が未考慮 | `roi_to_device()` を全 ratio 座標に適用 | 68 箇所完了、残 8 箇所修正中 |
| Wi-Fi 画像破損 | `adb screencap -p` の TCP 転送でパケット損失 | 3 回リトライ + ADB 再接続 + サイズ検証 | 完了 |
| x 誤検出 | Canny/輝度の閾値が低すぎ (15px/25px) | テンプレートマッチング一元化 (>= 0.70) | 完了 |
| Unity 入力フリーズ | Unity が内部状態を失い touch event を無視 | `force-stop` → `am start` で強制復帰 (最大 3 回) | 完了 |
| ダイアログ誤検出 | 枠中心判定が画面端まで許容していた | 枠中心 X を 20%-80% に厳格制限 | 完了 |
