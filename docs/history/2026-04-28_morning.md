## 原因

設計意図と実装の乖離:

| 段階 | phash 使用 | 設計意図との整合 |
|---|---|---|
| Step A | ✅ phash 即決 + 中間域 dHash + Jaccard + 直径制限 | 整合 |
| Step B 段階1 (split) | ✅ クラスタ内動作 (暗黙的に phash 整合) | 整合 |
| Step B 段階2 (split items 再統合) | ❌ dHash のみ | **違反** |
| Step B 段階3 (時系列連続性) | ❌ dHash のみ | **違反** |

## 修正内容 (`crawler/tools/ap/background_worker.py`)

### 段階1
- `split_items` 型: `list[tuple[int, str]]` (id, dhash) → `list[tuple[int, str, str]]` (id, phash, dhash)
- SELECT に `phash` 追加

### 段階2 (`_step2_resplit_items` 相当)
- 新規閾値: `PHASH_TH_STRICT=25`, `PHASH_TH_LOOSE=30`
- ループ変数: `for sid, dhash` → `for sid, phash, dhash`
- prev_screen / rep の SELECT に `phash` 追加
- 判定:
  - 旧: `RULE_A: d_d < 25` / `RULE_B: d_prev_d < 20 AND d_rep_d < 35`
  - 新: `RULE_A: d_d < 25 AND d_p < 25` / `RULE_B: d_prev_d < 20 AND d_rep_d < 35 AND d_p < 30`

### 段階3 (`_step3_temporal_continuity` 相当)
- 新規閾値: `STEP3_PHASH_TH_STRICT=25`, `STEP3_PHASH_TH_LOOSE=30`
- `all_data` SELECT に `phash` 追加
- `rep_info_map` のタプル: `(dhash, norm_text)` → `(dhash, phash, norm_text)`
- メンバーループで `mph = m["phash"]` を取得し、判定条件に phash 追加
- 新規クラスタ生成時に `rep_info_map[next_cid] = (mdh, mph, m_norm)` に拡張
