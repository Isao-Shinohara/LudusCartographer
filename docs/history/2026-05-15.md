## カテゴリ別の主要作業

### 1. Gemini コスト調査 (ultrathink)

**`lc_api_usage` テーブル全数調査** で根本原因を特定:

| 日 | calls | avg_in | avg_out | 推定 USD |
|---|---|---|---|---|
| 5/4 | 5,081 | 1,581 | 122 | $1.05 |
| 5/5 | **7,845** | 1,596 | **1,941** | **$7.34** ← 異常 |
| 5/6 | 3,523 | 2,037 | 109 | $0.87 |
| 5/7 | 342 | 2,117 | 103 | $0.09 |
| **累計** | **16,791** | 1,695 | 969 | **$9.36** |

**決定的事実**:
- 16,791 件中 **100% が `hq_ocr`** (Gemini OCR)。anchor / tag judgment は 0 件
- 5/5 のスパイクは MAX_TOKENS 8181 が 1,790 件 (前セッション `707ab21` で修正済)
- 通常稼働は **$0.87/日 = 月 $25-50**

**根本原因**:
1. 巨大プロンプト 約 1,200 tok を毎回送信、Implicit Cache 未活用 (format で動的値混入)
2. 事前棄却なし (artifact/sentinel 全 36% にも API call)
3. 降格代表に Gemini 実行 (has_gemini 4,370 > reps 3,202 = 27% 無駄)
4. multi バッチ dormant、1 画像 1 リクエスト
5. テキスト一致クラスタへの再 OCR
6. 30秒間隔は単独ではコスト無関係 (撤回)

### 3. 案 C 実装 (`5bd2ab3`)

**設計**: クラスタリング loop で cluster_id が変動しなかった連続回数を `cluster_stable_loops` カラムに記録し、Gemini は閾値 2 以上のみ対象にする。

**遷移仕様**:
- 新規 screen: loop1 で cluster_id 確定 (値 0、snapshot 外)
- loop2: snapshot に入る → 一致なら +1 (=1)
- loop3: +1 (=2) → Gemini 対象 (約 30 秒の遅延)

**実装変更**:
- `screen_recorder.py:_migrate` + `batch_processor.py:_migrate` に `cluster_stable_loops INTEGER DEFAULT 0` 追加
- `background_worker.py`:
  - 定数 `_GEMINI_CLUSTER_STABLE_THRESHOLD = 2` 追加
  - `_take_cluster_snapshot()` ヘルパー (loop 開始時の cluster_id 取得)
  - `_mark_cluster_stability()` ヘルパー (loop 末尾で一致 +1、不一致 0、新規不変)
  - `_run_incremental_clustering` の前後で snapshot + mark を呼ぶ
  - 早期 `return` 経路でも mark を呼ぶ (新規 screen なし時も既存 screen は安定 +1)
  - `_run_gemini_batch_correction`: `running` は `cluster_stable_loops>=2` 必須、`completed` は無条件

**テスト**: pytest 14 件追加、全 pass
- TestTakeClusterSnapshot (3)
- TestMarkClusterStability (5)
- TestMultiLoopProgression (2)
- TestGeminiQueryStabilityFilter (3)
- TestMigration (1)

### 4. 案 A 実装 (`e3f0b03`)

**設計**: Gemini Implicit Cache (1024+ tok 共通 prefix で 75% 割引) を活用するため、プロンプトを SYSTEM (固定) と USER (動的) に分離。

**実装変更** (`crawler/tools/ap/ocr_correction.py`):
- `_GEMINI_SYSTEM_PROMPT` / `_GEMINI_USER_TEMPLATE` (single 用) に分離
- `_GEMINI_BATCH_SYSTEM_PROMPT` / `_GEMINI_BATCH_USER_TEMPLATE` (batch 用) に分離

- 後方互換: `_GEMINI_PROMPT` / `_GEMINI_BATCH_PROMPT` は SYSTEM + USER 連結版を維持 (既存 4 テスト pass)

**テスト**: pytest 13 件追加、全 pass

- TestUserTemplateHasPlaceholders (3): USER に必要な placeholder あり

- TestSystemInstructionInRequestBody (3): body 構造検証、SYSTEM に動的値混入なし、複数リクエスト間で SYSTEM 完全同一
- TestSdkSystemInstruction (1): SDK 側も system_instruction を渡す
