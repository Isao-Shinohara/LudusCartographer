## ⚠️ 未解決: process_session_bg 空回り問題

### 症状
ダッシュボード「再開」ボタンを押しても Gemini OCR が処理されない。
- 100イテレーションが30秒で完走
- 処理件数 0 件 (324 → 260 の差は再起動前の auto_pilot bg_worker による)

### 調査経緯
1. 当初、PHP 文字列連結で Python スクリプトを生成しており `def _pending():` が semicolons と同行になる構文エラーで API が null を返した
2. HEREDOC 構文に書き換えて API 呼び出しは成功 → ただし依然 0 件処理
3. `2>/dev/null` でエラーが見えず、長時間調査

### 根本原因
- PHP サーバー (`php -S localhost:8080`) は環境変数に `GEMINI_API_KEY` を持たない
- shell rc ファイル (`.zshrc`/`.bashrc`) にも `GEMINI_API_KEY` なし
- `.env` ファイルは `crawler/config/.env` に存在
- `auto_pilot.py` は起動時に `load_dotenv(crawler/config/.env)` で読み込んでいる
- しかし PHP から起動された Python (`search.php:274` の HEREDOC) は `load_dotenv()` を呼んでいない
- → `os.environ.get("GEMINI_API_KEY", "")` が空文字 → `_run_gemini_batch_correction` が即 `return` で離脱

### 修正済み (未コミット・未テスト)
**ファイル**: `web/public/api/search.php`

1. HEREDOC 内に dotenv ロードを追加:
   ```python
   import json, sqlite3, os
   ```
