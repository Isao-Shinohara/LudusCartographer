### 5. _remerge_text_clusters (旧 _remerge_after_gemini) — 拡張
PaddleOCR HQ も remerge トリガーに拡張。

- WHERE 拡張: `ocr_text_gemini IS NOT NULL OR ocr_text_hq IS NOT NULL`

- **dhash 併用**: テキスト空同士の判定で phash + dhash 両方 < 閾値で統合 (122130 vs 122131 のような phash 偶然近・dhash 遠を弾く)

### 6. Step A 中間域 — Jaccard 類似度追加
phash 中間域 (8〜40) で `phash_jaccard_similarity < 0.3` なら別判定 (`phash_low_jaccard`)。

- Hamming 距離は「両方 0」を「同じ」と数えるため、疎な phash ペア (set bit が少ない明るい単色寄り画像) は実質的に違うのに距離が小さく出る
- Jaccard は set bit の重なり度を測るので、疎ペアの実質類似度を補正できる
- 例: 125436 (15 bits) ↔ 125437 (10 bits): Hamming 19、Jaccard 0.136 → 別判定

`lc/image_comparator.py:phash_jaccard_similarity` を新規追加。

## 主要なやり取りの抜粋

### Q: ORB と dHash どちらを採用？
A: dHash 一本化決定。ORB は 3D キャラ・動画フレームで match_rate が 0〜0.1 帯に落ちるため実用にならない。dHash は coarse な構造を見るので動画でも安定。

### Q: phash の中間域で疎な hash 同士が誤統合される (125436/437)
A: Hamming は「両方 0」を「同じ」と数えるため疎ペアで距離が小さく見える。Jaccard 類似度を併用して set bit 重なり度で判定。

### Q: 段階 3 で 1 pass のみだと連続フレームが取り残される (125546/547)
A: prev_cid_map が静的なため、直前 screen 移動後に取り残し。完全収束まで反復で解決。

### Q: 663 (空 text) と 664 (text あり) を同じクラスタにしたい (テキスト盲目はよくない)
A: 「両方 text あり時のみ text 一致を要求、片方空は dHash 判定」というルールを段階 3 に導入。

### Q: 閾値を緩めたら tap 起点のレコード比率が上がる？
A: 正しい。auto (動画フレーム) は緩和で大幅に統合される一方、tap 後のシーン変化は phash/dHash 距離が大きいので変わらない。結果として相対比率は tap 起点が増える。
