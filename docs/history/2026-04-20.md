# 2026-04-20 セッション要約

## 概要
Gemini画像判定によるアンカー精度向上、あいまい一致の導入、バージョン管理UI、Cost タブなど大規模改善。

## 主な作業

### 1. Gemini 画像判定 (P4)
- テキストのみ判定 → **画像ペア送信**に変更（flash-lite が別画面と誤判定したため）
- `gemini-2.5-flash` でテスト → 正しく判定、ただしバッチ送信で `Server disconnected`
- **最終形: flash-lite + ThreadPoolExecutor 5並列** (1ペアずつ並列送信)
  - 1ペア1.3秒、134件を約35秒で処理
- `files.upload` → `Part.from_bytes` インライン送信に変更（5秒→1.3秒/ペア）
- P1/P3 で採用されたアンカーも P4 で検証（テキスト完全一致/前方一致はスキップ）
- `prefer` フィールド追加（テキスト採用判断: A=セッション, B=マスター）
- `lc_anchor_judgments` テーブルに `prefer` カラム追加
- JSON レスポンス形式に変更

### 2. あいまい一致 (P1/P2)
- テキスト完全一致/前方一致に加え、**あいまい一致** (sim≥動的閾値, phash<20, 候補1件) を追加
- テキスト長に応じた動的閾値: 短文(<20字)=0.5, やや短い(<50字)=0.65, 中間(<200字)=0.8, 長い(200字+)=0.7
- `_text_similarity()`: SequenceMatcher + bag-of-words (Jaccard係数) の高い方を採用
- OCR ノイズ除去 `_normalize_for_comparison()`:
  - 数値トークン除去（ダメージ値、Lv等）
  - ノイズ語辞書から除去（AUTO, SKIP, MANUAL 等 + Gemini 自動抽出）
  - 英字-日本語境界スペース除去
  - Episode番号・1文字ノイズ除去
- P4 発見候補の閾値緩和: phash<15, sim≥0.5

### 3. LIS 順序チェック削除
- アンカーの `_verify_consistency` (LIS) を削除
- 「マッチが正しければ全採用」— 順序はSafeInsert側で担保
- 棄却は Gemini 検証のみ（理由: 「Gemini画像判定で別画面と判定」）

### 4. フェーズ番号振り直し

- `PHASE_DEFS` で表示名・色・順序を一元管理、フロントはバックエンドから動的取得

### 5. バージョン管理

## 技術的知見
- Gemini flash-lite: 1ペア画像判定は正確に動作（バッチ詰め込みが原因で失敗していた）
- `files.upload` は 1画像5秒以上 → `Part.from_bytes` インラインで1.3秒
- ThreadPoolExecutor + Semaphore で API 並列化が有効（asyncio はサブプロセスでデッドロック）
- PHP ビルトインサーバーはシングルスレッド: DB 経由の進捗ポーリングは不適切
- pyc キャッシュ問題: PHP から起動された Python が古い pyc を使う → `-B` フラグで解決
