# OCR 改善計画

## 概要

PaddleOCR/Vision の生テキストを段階的に改善し、最終的にユーザー修正 + Gemini Flash + 自動学習の3層で高精度なテキストデータを構築する。

---

## Phase 1: ダッシュボードでの手動テキスト編集

**目的**: 修正データの基盤を作る。他の全フェーズの前提。

- Final タブのモーダルで OCR テキストを編集・保存できる UI
- `lc_master_nodes` に `ocr_text_manual` カラム追加
- 表示優先順位: `ocr_text_manual` > `ocr_text_gemini` > `ocr_text_hq` > `ocr_text`
- 修正履歴の記録（誰が・いつ・何を変えたか）

**完了条件**: ダッシュボードで OCR テキストを編集・保存でき、修正テキストが優先表示される

---

## Phase 2: 修正ルールの自動展開

**目的**: 1件の修正を最大限活用し、手動修正の負担を減らす。

- 修正ルールテーブル `lc_ocr_corrections` (`before_text`, `after_text`, `created_at`)
- 適用範囲:
  1. 同クラスタ内の画像 → 同じ修正を一括適用
  2. 同セッション内の他画面 → 同パターンの部分置換
  3. 全セッション横断 → 同パターンの部分置換
- ダッシュボードに「適用候補 N 件」の確認 UI（自動適用ではなくユーザー確認後に適用）
- ルールの管理画面（一覧・編集・削除）

**完了条件**: 1件の修正が関連する画面に自動提案され、確認後に一括適用できる

---

## Phase 3: Gemini Flash による OCR 補正

**目的**: 大量の誤読を AI で自動補正。手動修正は Gemini が拾えない箇所のみに。

### 実行タイミング

自動操縦中にバックグラウンドで段階的に実行（セッション完了後にまとめてではない）:

1. **自動操縦中**: PaddleOCR のみで操縦判定（高速、Gemini 不要）
2. **100枚ごと**: バックグラウンドで未処理の代表画面のみ Gemini Flash に送信
3. **セッション完了時**: 残りの未処理代表を処理 → 補正テキストで再クラスタリング → マージ

### コスト見積もり

| 項目 | 値 |
|---|---|
| 入力トークン/枚 | ~400 (画像250 + OCRテキスト100 + プロンプト50) |
| 出力トークン/枚 | ~100 |
| 代表画面数/周回 | ~150枚 |
| 1周回あたりコスト | **約 $0.01（約1.5円）** |
| 10周回 | 約15円 |

※ トークン量課金のため、分散実行でもまとめてでもコスト同一

### 実装詳細

- `lc_screens` に `ocr_text_gemini` カラム追加（代表画面に保存）
- Gemini Flash API: 画像 + PaddleOCR 結果を送信し補正テキストを取得
  - プロンプト: 「ゲーム画面のOCR結果です。画像と照合して誤読を修正してください」
- Phase 2 の修正ルールを few-shot examples として Gemini に渡す（精度向上）
- ダッシュボードで PaddleOCR / Gemini / 手動修正 の diff 表示
- **Gemini 補正後に再クラスタリング**: 補正テキストでセリフ違い等を正しく分離
- **PaddleOCR はフォールバックとして残す**: Gemini API キー未設定 or API エラー時は PaddleOCR HQ で処理

**完了条件**: 代表画面に Gemini 補正が適用され、補正テキストで再クラスタリング・マージが行われる

---

## Phase 4: 次回周回への自動適用

**目的**: 蓄積した修正知識を周回ごとに自動で活かし、周回を重ねるほど精度が上がる。

- 周回開始時に修正ルール DB をロード
- PaddleOCR 実行後の自動補正パイプライン:
  1. 修正ルール（Phase 2）による部分置換
  2. phash 近傍の既知テキスト流用（過去の修正済みテキスト）
  3. Gemini Flash は新規画面（既知パターンに該当しない）にのみ実行（コスト最適化）
- 周回ごとの精度推移をダッシュボードで可視化

**完了条件**: 新規周回で過去の修正が自動適用され、Gemini 実行が新規画面のみに最適化される

---

## 実装順序

Phase 1 → 2 → 3 → 4 の順。各フェーズ完了後に効果を評価してから次へ進む。

## 備考

- Gemini Flash は極めて安価（1周回 ~1.5円）なので代表画面全適用でも現実的
- PaddleOCR のファインチューニング（ゲームフォント特化）は Phase 4 以降の発展として検討
- 各フェーズの詳細設計はブラッシュアップ中
